# Content architecture

## Default spine (10–18 working slides for a client readout)

Adjust count to the brief. Never go below 7 working slides plus title. Never keep two slides that make the same point.

| # | Role | Action-title test | Typical recipe |
|---|---|---|---|
| 1 | Title lockup | Would a partner know author team, client, date, document type in 3 seconds? | Cover lockup |
| 2 | Agenda | Does the list match the slides that follow? | Agenda contract |
| 3 | Situation | What is true *today*, with a number? | Governing chart + rail |
| 4 | Complication | What moved, and by how much? | Waterfall / bridge / gap |
| 5 | Diagnosis | Where exactly does value leak? | MECE tree, method + facts |
| 6 | Options | What are the real choices, not a fake menu? | Choice split / 2×2 |
| 7 | Answer | What do we recommend, named? | Recommendation banner + 3 supports |
| 8 | Value | What is it worth, under which assumptions? | Economics exhibit |
| 9 | How | What operating model / levers make it real? | Lever list or pyramid |
| 10 | Roadmap | What happens in 30 / 90 / 365 days? | Phase chevrons + owners |
| 11 | Ask | What does this room owe us? | Decision frame |
| 12+ | Appendix | Workings only | Divider + exhibits |

Thought-leadership briefs compress to: cover → snapshot box / governing claim → 3–5 exhibit pages → implications → authors.

Public-sector briefings add a scope box on the context slide.

M&A / joint-venture briefs insert a value-contribution table before the answer.

Transformations insert a “from / to” operating-model slide before the roadmap.

## Action titles

A title is a claim.

Illegal: Overview, Financial Analysis, Our Idea, Roadmap, Primary Research, Recommendations, Context.
Legal: "Category volume has declined 11 percent since FY22."
Legal: "The operator must balance reliability, cost, and transition timing."
Legal: "Challenger brands can take a third of growth in disrupted categories."

Pattern: subject + verb + consequence. Keep under 16 words. Put the label (“Recent Context”) in the eyebrow, not the title.

Subtitles exist to scope units and dates (“$ billions, fiscal years ending 30 Sept”), not to repeat the title.

## Pyramid inside a slide

1. Title = answer
2. Exhibit = evidence
3. Rail = the 3–5 supports or drivers
4. Footer = SOURCE + identity + page

Do not end a working slide with “in conclusion”. The title already concluded.

## One-breath recommendation

By the end of the answer slide the partner should be able to say

> Do X, named Y, for owner Z, because metric M, starting in window P, asking this room for Q.

Write that sentence in Pass 1 and print a shortened form as the recommendation banner.

## Evidence hierarchy

1. Client / administrative exhibits
2. Primary work the team ran (n + method)
3. Named secondary (industry report, capital-markets data, ministry publication)
4. Assumption, labelled as assumption

Never present an assumption in the same visual weight as an exhibit number.

## Slide budget by engagement type

- Board readout — extra diagnostic + extra option split, thinner narrative
- Transformation — extra from/to operating model + extra value
- White paper / brief — snapshot box + 4 exhibits, no team process slides
- Ops / cost — extra lever list + extra organisation
- Policy / public — extra scope box + extra stakeholder map

## What to cut first when over the slide cap

1. Second diagnostic that restates the first waterfall
2. Frameworks that do not change the recommendation
3. Duplicate roadmap (keep one Gantt)
4. Decorative “thank you”
5. History-of-the-project slides the room does not need
