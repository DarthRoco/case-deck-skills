# Content architecture

## Default spine (8–14 main slides)

Adjust count to the brief. Never go below 7 content slides plus cover and close. Never keep two slides that make the same point.

| # | Role | Insight-title test | Typical recipe |
|---|---|---|---|
| 1 | Cover | Would a judge remember team + case in 3 seconds? | Cover identity |
| 2 | Situation | What is true about the market and the firm *today*? | Snapshot strip + hero numbers |
| 3 | Fracture | Where exactly does value leak? | Journey gap, 2×2, issue grid |
| 4 | Choice | Why this option, not the obvious alternative? | Comparison table or attractiveness matrix + recommendation banner |
| 5 | Idea | What is the named thing? | Idea banner + 3–5 capability cards |
| 6 | Mechanism | How does a user / operator experience it? | UI flow, process, org, storyboard |
| 7 | Proof | Why will it work commercially and humanly? | Research module + financial trio, or two slides if both are heavy |
| 8 | Build | What happens in month 1, year 1, year 3? | Phase roadmap + owners |
| 9 | Risks / enablers | What would kill it, and the counter? | Risk matrix or policy pack |
| 10 | Close | Three pillars, same numbers, one ask | Conclusion pillars |
| 11 | Thanks | Faces again | Close |
| 12+ | Annexure | Workings only | Divider + dumps |

Marketing-heavy briefs insert a campaign-360 slide before the financial trio.
People / merger briefs insert an operating-model + talent slide before the roadmap.
Analytics briefs replace situation + fracture with dashboard + EDA + model comparison.

## Insight titles

A title is a claim.

Illegal: Overview, Financial Analysis, Our Idea, Roadmap, Primary Research, Recommendations.
Legal: "92% will try a healthy instant breakfast if it still tastes like masala oats."
Legal: "Outsourcing the fab saves 27% and frees capital for IC design."
Legal: "Pilot Mumbai–Ahmedabad–Chennai in year 1; breakeven in year 3."

Pattern: metric or actor + verb + consequence. Keep under 16 words. Put the label ("Financials") in the navigator, not the title.

Subtitles exist to scope the slide ("Tier-1 and Tier-2, disposable income > ₹6 L") not to repeat the title.

## Pyramid inside a slide

1. Title = answer
2. First row = the 3–5 supports
3. Second row = evidence (chart, quote, table)
4. Footer = source + navigator

Do not end a slide with "in conclusion" inside the body. The title already concluded.

## One-breath recommendation

By the end of slide 4–5 the judge should be able to say

> Do X, named Y, for audience Z, because metric M, starting in place P.

Write that sentence in Pass 1 and print a shortened form as the recommendation banner.

## Evidence hierarchy

1. Client / case exhibits
2. Primary research the team ran
3. Named secondary (industry report, investor presentation, ministry publication)
4. Reasonable assumption, labelled as assumption

Never present an assumption in the same visual weight as an exhibit number.

## Slide budget by case type

- Product / brand — extra journey + extra campaign slide, thinner industry 2×2
- Operating model / merger — extra org + extra talent + extra funding, thinner persona
- Infra / public — extra process + extra policy + unit econ
- Social — extra persona, honest small-budget line
- Analytics — extra dashboard + model table, recommendation still named

## What to cut first when over the slide cap

1. Second persona (keep one hero persona + a TG table)
2. Generic strategy frameworks if a better fracture visual already exists
3. Duplicate roadmap (keep one Gantt, move the other to annexure)
4. Decorative "thank you quotes"
5. Frameworks that do not change the recommendation
